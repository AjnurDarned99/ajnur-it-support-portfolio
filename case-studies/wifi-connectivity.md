# Practice Case Study: Wi-Fi Connected, No Internet

**Type:** Simulated troubleshooting exercise  
**Category:** Connectivity  
**Status:** Resolved for the purpose of this fictional example

## Reported issue

A fictional user reports that their laptop connects to the expected Wi-Fi network, but websites do not load. The issue reportedly started that morning.

## Initial questions

- Is one device affected, or are multiple devices/users affected?
- Does the network icon show connected, limited connectivity, or disconnected?
- Do approved internal services work, or do all destinations fail?
- What exact error is visible, and approximately when did it begin?

## Safe diagnostic sequence

1. Confirm scope and capture the exact symptom without asking for credentials.
2. Verify the device is connected to the expected Wi-Fi network.
3. Check whether another approved website or service works.
4. If permitted, review basic connection details such as IP address and default gateway; do not make router or shared-network changes without authorisation.
5. Reconnect the device only if appropriate under local policy and retest one known destination.
6. If the issue persists, record the operating system, timestamp, scope and findings for escalation.

## Fictional outcome for practice

The simulated user restored access after reconnecting to the expected network. The note should state this as the observed result in the scenario, not as a real incident.

## Escalation criteria

Escalate broader outages, an invalid address affecting multiple users, a suspected security event, or any change requiring network administrator privileges.

## What a good ticket should include

- User/device scope (using anonymised labels)
- Start time and exact error
- Checks performed and each result
- Final observed outcome
- Any remaining risk or follow-up
